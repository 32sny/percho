## 一、目标与阶段边界

### 1.1 交付目标

用户无需点击进入会话，停留在左侧某个会话条目上即可看到：

1. 完整的已保存会话标题，自动换行、不做行数裁剪，可选中复制。
2. 当前真实可用的运行状态、模型、目录、创建时间和最后活动时间。
3. 当前分支的首条有效用户文本首行，作为独立的“首条提问”预览；不覆盖会话名称。
4. 历史读取异常或达到资源限制时，保留基础详情并给出明确说明。

项目分组与日常分组使用同一实现。悬停本身不切换当前会话，不触发推理，不创建或重新打开会话实例。

### 1.2 建议展示结构

```text
完整的已保存会话标题
较长时自然换行，可选择复制

工作中 / 等待应答 / 完成未读 / 空闲 / 未加载

首条提问（当前分支）
与标题不同的原始首行安全预览……

模型：仅有已知数据时显示
目录：完整工作目录
创建：本地时间
最后活动：本地时间
```

这是信息结构示意，不是最终像素设计。实施沿用项目现有字体、圆角、阴影、语义颜色和深浅主题，不另建视觉系统。

### 1.3 关键产品口径

| 情况 | 本方案的处理 |
| --- | --- |
| 名称完整保存，仅列表显示不下 | 浮层完整显示现有名称 |
| 新普通会话自动命名 | 完整保存用于命名的首行；列表仍然 CSS 省略 |
| 旧会话名称已被自动命名截短 | 保留旧名称；另外读取并显示首条提问，不宣称恢复了原名称 |
| 用户手工改过会话名称 | 始终尊重现有名称，不自动用消息替换 |
| 首条提问与标题相同 | 隐藏重复的提问区块 |
| 历史发生分支或撤回 | 预览以当前分支为准，明确标注；不承诺它必然等于最初命名时的文本 |
| 首条消息只有图片或没有可显示文本 | 跳过，寻找当前分支首条有效用户文本；没有则不展示提问区块 |
| 提问包含多行 | 首版展示首行，不把它称为完整任务正文 |
| 超大文件或异常格式 | 预览明确不可用；完整已保存标题仍可查看 |

“完整标题”指完整的已保存名称。旧名称已截掉的部分，不能从名称字段中凭空恢复；独立提问预览用于补充理解，不是静默修复或批量迁移历史名称。

### 1.4 明确非目标

本次不包含：

- 创建后台子会话、自动派工、自动回报、可靠投递和执行续跑。
- 聊天区编排汇总卡片、工作流画布。
- 编排父子关系、创建来源、最近往来和通用失败原因的新增数据系统。
- 浮层里的子会话跳转、返回父会话、停止任务等操作。
- 历史会话批量改名、迁移或改写。
- 内置子代理命名规则、Agent/PiFlow 行为、执行器开关和工具加载策略调整。
- UI 插件槽位扩展和 LAN 网页端同等功能。
- 在悬停时调用模型生成摘要。

**本轮规划补核：** 后端已经存在 `peekSessionMessages()`，未加载会话可纯解析文件，不需要 `SessionManager.open()`。因此不是从零建设历史读取系统；本方案新增的是面向悬停的、有资源限制的轻量 DTO 和桌面 IPC 通道。

### 2.2 不能直接复用或需要调整的部分

1. **自动名称保存已截短。** `autoNameSession()` 当前超过 30 个 UTF-16 码元就截短加省略号；普通会话新命名需取消该保存前裁剪。
2. **现有 Tooltip 不适合。** 它单行、不可交互、无 Portal，不能直接满足跨容器的详情卡。
3. **现有菜单定位不是侧向定位。** `placeMenu()` 默认为下沿左对齐；新卡片采用专用纯定位函数，不改变现有菜单的默认行为。
4. **历史列表没有模型信息。** 首版不额外解析历史模型，缺失时隐藏。
5. **不能把状态直接当业务结论。** `done` 表示完成未读；`active` 表示内存加载，不是模型运行中。
6. **现有 peek 返回完整历史。** 直接给每次悬停调用会带来多余读取、对象构造和 IPC 传输；应限制读取规模，只返回一条预览。
7. **现有路径定位含全量枚举兜底。** 悬停通道不采用该兜底；带 cwd 精确定位失败即明确不可用，不为一次悬停遍历全部项目会话。
8. **不使用子会话导航。** 当前 `openSubagentSession()` 默认以选中会话作为返回来源；本版没有子会话链接，避免把这一不匹配语义带入悬停功能。

## 三、架构决策

### 3.1 总体结构

```text
SessionRow：触发、焦点、标题与基础元数据
        │
        ▼
Sidebar 级单实例悬停控制器
        │
        ├── SessionHoverCard：Portal 渲染、复制、滚动
        ├── positionSessionHoverCard：专用位置计算
        └── 预览查询：缓存、去重、目标版本校验
                     │
                     ▼
             getSessionHoverPreview IPC
                     │
                     ▼
           后端只读、受限的当前分支预览
```

不引入新的浮层依赖包；复用 React、现有状态管理和测试基础。

### 3.2 前端浮层行为

推荐参数作为首版实现默认值：

| 行为 | 规则 |
| --- | --- |
| 鼠标打开 | 在同一条目停留 300ms 后打开 |
| 键盘查看 | 行获得键盘焦点后可打开；聚焦卡片无需改变会话选择 |
| 关闭缓冲 | 离开行与卡片后延迟 200ms 关闭；移入任一区域取消关闭 |
| 主体宽度 | 目标 360px，最大不超过视口宽度减 16px |
| 高度 | 不超过视口高度减 16px，超高内容内部滚动 |
| 默认位置 | 会话行右侧，间隔 8px；不足时左侧，再夹入视口 |
| 边距 | 距离视口边缘至少 8px |
| 标题 | 保留文本，不加 ellipsis 或 line-clamp；无空格长串也换行 |
| 滚动与尺寸变化 | 侧栏/外部滚动或窗口 resize 时关闭，避免失去锚点；卡片内部滚动不关闭 |
| 原有行操作 | 点击选中、右键菜单、拖拽开始时关闭卡片，原操作继续 |
| Escape | 关闭并抑制当前停留区域立刻重新打开；离开后再次进入或重新聚焦才打开 |
| 单实例 | 整个侧栏同时只渲染一个卡片 |

卡片作为独立可交互浮层而不是不可交互 tooltip：使用非模态语义，明确关联标题与触发行；允许从行通过键盘进入卡片再返回，不自动抢焦点，不陷住 Tab。Escape 在焦点处于卡片内时返回触发行；触发行已消失则不强制聚焦失效元素。

Portal 挂在 Sidebar 控制器的渲染分支中，不作为会话行 button 的交互子节点。卡片点击、文本选择不触发行的选择、右键或拖拽逻辑；事件测试和真实界面验证均需覆盖。

层级遵守宿主现有弹窗层级；信任或设置等模态界面出现时关闭卡片，不通过无限提高 z-index 覆盖模态界面。状态色和深浅主题沿用语义 token，动画尊重减少动态设置。

### 3.3 标题保存策略

仅修改普通会话的 `autoNameSession()`：

- 保留“已有名称不覆盖”的行为。
- 保留现有文本块提取、首行选择、空文本处理和 Skill 安全格式化逻辑。
- 保存完整首行，不再执行原来的 30 码元裁剪。
- 列表继续使用 CSS 单行省略；浮层读取原始名称。
- 不修改内置 runner 的 `subagentSessionName()`，其现有标题测试仍应通过。
- 不迁移旧会话，不改写既有 session_info。

命名和预览使用同一个后端纯函数提取“安全首行”，避免新命名使用一套规则、预览使用另一套规则。对疑似未完整解析的 Skill 展开内容应返回不可展示，不把内联正文退化成普通文本显示。

### 3.4 预览 IPC 契约

新增桌面方法 `getSessionHoverPreview`，通道建议为 `session:hoverPreview`。它只返回预览，不返回完整历史、模型密钥、工具参数或内部消息字段。

```ts
interface SessionHoverPreviewRequest {
  sessionId: string;
  cwd: string;
}

type SessionHoverPreviewResult =
  | {
      status: "ok";
      sessionId: string;
      source: "current-branch-first-user-text";
      text: string;
    }
  | {
      status: "empty";
      sessionId: string;
    }
  | {
      status: "unavailable";
      sessionId: string;
      reason:
        | "not_found"
        | "identity_mismatch"
        | "invalid_history"
        | "read_failed"
        | "limit_exceeded"
        | "unsafe_projection";
    };
```

要求：

1. 请求必须携带来自目标 SessionMeta 的 ID 与 cwd，不接收任意用户文件路径。
2. 返回中保留 sessionId，前端同时校验本地请求代次，迟到结果不能覆盖当前卡片。
3. 已加载会话读取其当前分支，不用模型压缩后的上下文代替完整分支。
4. 未加载会话按 cwd 和 ID 精确定位，校验会话头 ID 与目录身份；失败不全量枚举，不自动 open/create。
5. 历史分支语义复用 `messages.ts`；只读提取首条可用用户文本，不使用另一分支的早期消息冒充当前提问。
6. `sourceText` 不进入 DTO，不进入可访问文本或复制内容。Skill 仅显示安全命令形式及用户参数。
7. 空预览隐藏区块；不可用显示对应轻量文案，不弹 toast 打断用户。
8. IPC 自身失败也降级为“预览暂不可用”，基础卡片保持可用。
9. 不在工具日志中记录原始提问正文，仅允许必要的错误类别和会话标识。

### 3.5 读取限制与性能边界

本方案选择“轻量、有界、诚实降级”，不承诺对任意大小历史文件都即时生成预览：

- 未加载历史单次最多读取 **8 MiB**；超过限制返回 `limit_exceeded`。
- 读取过程也必须限量，不能仅在 readFile 之前 stat 一次后无限读取增长中的文件。
- 预览首行 UTF-8 大小最多 **128 KiB**；超过限制返回不可用，不静默截断后声称完整。
- 对已加载分支进行同样的资源预算检查；不能通过内存路径绕过限制。
- 损坏分支、重复冲突 ID、循环父引用等无法可靠确定内容时，失败关闭预览；不得死循环或返回猜测文本。
- 这两个限制不用于裁剪标题字段；标题仍完整展示已保存名称。

用户可见文案示例：**“此会话较大，首条提问预览暂不可用；可进入会话查看。”** 首版不在该提示上隐式打开会话。

前端仅在卡片实际打开后请求预览，不在鼠标刚进入或整个列表渲染时批量请求。缓存建议：

- 键包含会话 ID、cwd、modifiedAt、messageCount。
- 最多保留 100 项，成功/空结果缓存 30 秒，失败缓存 5 秒。
- 相同键的在途请求复用。
- 全侧栏最多一个在途请求，快速切换只保留最新待请求目标，不堆积所有掠过条目。
- 会话删除、移动、历史撤回或重新加载时失效；卡片标题与状态仍从当前元数据和 store 实时读取，不被预览缓存冻结。

上述限制是首版的显式取舍，验收时要验证超限提示，不能把未覆盖的大历史标为完整支持。

### 3.6 模型与状态展示

| 数据 | 展示规则 |
| --- | --- |
| modelLabel/model | 目标会话当前已有值才显示；不借用当前窗口其他会话的模型 |
| 无历史模型 | 隐藏模型行，不在本版额外解析历史模型 |
| attention | 等待应答，覆盖权限和扩展对话请求 |
| working | 工作中 |
| done | 完成未读，不使用“验收成功”措辞 |
| idle 且会话已加载 | 空闲，不暗示上一轮成功 |
| 没有实时状态或会话未加载 | 未加载/无实时状态，不推断任务结局 |
| createdAt/modifiedAt | 分别显示创建与最后活动；缺失时间不伪造 |

普通会话不出现虚构的创建来源、子会话和失败原因区块。

## 四、执行状态机与核心业务时序

### 4.1 浮层状态机

```text
关闭
  └─ 进入目标行 → 等待打开
                     ├─ 300ms 前离开 → 关闭
                     └─ 到时仍为当前目标 → 已打开
                                            ├─ 显示标题与基础信息
                                            ├─ 请求/读取预览缓存
                                            ├─ 移入卡片 → 保持
                                            ├─ 离开双方 → 等待关闭
                                            │              ├─ 200ms 内回到任一方 → 保持
                                            │              └─ 超时 → 关闭
                                            └─ Escape/点击行/右键/拖拽/外部滚动/resize → 关闭
```

目标变化立即使旧目标的展示和代次失效。旧请求可以完成并受控缓存，但不得把旧标题、预览或错误提示写到新目标卡片。

### 4.2 后端只读时序

```text
校验请求
  → 查已加载会话并验证身份
  → 已加载：读取当前分支
  → 未加载：按 cwd + ID 精确找文件并验证会话头
  → 资源预算检查与受限读取
  → 依据既有分支规则确定当前分支
  → 提取首条有效用户文本的安全首行
  → 返回窄 DTO 或明确的 empty/unavailable
```

全程不调用会话创建、`SessionManager.open()`、模型 prompt、扩展加载、自动命名或历史写入。

### 4.3 故障与回退

- 预览失败仅影响提问区块，标题和基础详情正常显示。
- 新命名规则只作用后续自动命名，不修改旧数据，因此无需历史迁移回滚。
- 如实现阶段发现共享历史解析必须大规模重构，停止扩大改动，先回报并修订方案；不把重构静默塞进本功能。
- 可单独撤下悬停卡及专用 IPC；不能回滚用户在开发期间产生的其他工作区改动。
